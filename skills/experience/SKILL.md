# 体验：给执行体验的 Agent 看

写代码的 Agent 知道内部怎么实现，会不自觉地替用户补上缺的步骤。体验换一个只拿到用户材料的人，从用户的入口真的走一遍。全程中文，说话短。

## 动手前

- 读 RULES.md 的“用户是谁”。没写就问用户：用户是谁、平时用它做什么；是否写进 RULES.md 由用户决定，体验本身不写文件。
- 定一两个真实任务：用户指定的优先；没指定就从 README 里挑最常见的用法，说给用户听再开始。

## 派谁去

- 派一个没看过代码的子 Agent。只给它：用户身份、任务、README，以及用户能拿到的入口（安装命令、网址、界面、命令行）。不给源码路径、需求文件、这次改了什么。
- 宿主没有子 Agent 时，告诉用户，建议开一个新会话，把上面这些材料原样交给它。

## 子 Agent 怎么走

- 按用户身份理解 README，照着做；README 没写的步骤不自己补。
- 真的去操作：装、跑、点、读输出。只读文档、凭想象描述体验不算。
- 不改任何文件。走不下去就记下来，换下一个任务。

## 汇报

主 Agent 在对话里转述，每个问题一段：

- 想做什么，照 README 做了什么，看到了什么。
- 卡在哪一步；README 哪一段和实际对不上。
- 有多严重：走不下去、绕一下能过、只是别扭。

最后一句话说整体能不能用。修不修、怎么修由用户决定；体验本身不改文件。

## 不要做

- 不让子 Agent 读代码，也不在交给它的材料里透露实现。
- 不把“技术上能跑通”当成“用户能用起来”。
- 不为凑数报风格偏好；没发现问题就直说。
