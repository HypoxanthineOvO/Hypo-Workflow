# 清理：给执行清理的 Agent 看

Agent 会照着仓库里已有的写法继续写，烂写法也会被复制，文档和规则也越积越多。清理按项目自己的标准，把这些一次收拾掉。全程中文，说话短。

## 标准

- 以 RULES.md 和需求文件为准，尤其是“不能坏”。不按自己的口味重写能用的代码。
- 每一处都问：删掉它，会有人或 Agent 因此出错吗？不会就删；会，就留着或改写。

## 动手前

- 跑 hw check，把它报出来的东西当线索。
- 找这几类：
  - 没人调用的代码、重复实现的工具函数、只为“以后可能用”留的接口。
  - 和代码对不上的文档：需求文件的“现在”“代码”锚点、README 里的命令和说明。
  - 过时或重复的规则：RULES.md、分区 AGENTS.md 里已经不成立、或者说了两遍的条目。
- 先把清单给用户看：每处删什么、改成什么、为什么。用户确认后再动手。

## 动手

- 按清单做，不顺手扩大范围。碰到“不能坏”的东西、或者删了会改变用户能看到的行为，停下来问。
- 改代码时，同步改牵连到的需求条目和文档；文档按“只写现在”改写，不追加说明。
- 每处理完一类单独提交，提交格式照 AGENTS.md。

## 收尾

- 跑测试和 hw check。
- 在对话里汇报：删了什么、改了什么、哪些按用户意见留下了、还有哪些拿不准等用户决定。

## 不要做

- 不为了让检查变绿删测试、放宽断言或吞掉报错。
- 不改 AGENTS.md：它由 Workflow 安装和升级。
- 不动文档地图外的文件和 `archive/` 里的旧记录。
