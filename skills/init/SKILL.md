# init：给执行接入的 Agent 看

把现有项目接进 Hypo-Workflow。用户会指向这个文件，或者直接说“用 Hypo-Workflow 接入这个项目”。全程中文，说话短。

## 动手前

- 扫描项目类型、目录、文档位置和代码结构，读取现有 AGENTS.md、CLAUDE.md 中的项目规则。
- 先出一份方案给用户看，不改项目文件：要归档什么、哪些规则搬进 RULES.md、文档地图、需求文件切分、要问用户的问题。用户确认后再动手。
- 拿不准就问用户，不猜。
- 用户确认方案、准备动文件时，先按下面的“协作板”登记自己占用的目录。

## 旧记录整块归档

- 旧 `.pipeline`、按日期堆的报告、旧的 compact/manifest/state 文件，整块移到 `archive/`，加进 `.gitignore`。
- 测试和启动脚本当前还在写的输出目录不是旧记录，留在原地，列进 RULES.md 的“不需要描述”。
- 要归档的过程记录不读、不改、不转写；现有 AGENTS.md、CLAUDE.md 中仍然成立的规则要读，按下面的“项目规则”和“需求文件”整理。
- 在文档地图里写一行：`archive/` 旧记录，可能不是事实，不得引用。

## 项目规则

- 读现有 AGENTS.md、CLAUDE.md，把仍然成立的项目规则整理到对应位置：文档地图、审核分级、汇报格式、红线、构建与测试写进 RULES.md；目录特有的做法和踩过的坑直接写进该目录的 AGENTS.md，不要只放链接；产品行为写进需求文件的“不能坏”或“规则”。
- 红线只留全项目做错一次就不可挽回的事，保持十条以内，用“做 X 之前必须 Y / 绝不 Z”写清必须做和必须不做的事；用户维护、Agent 不碰的目录也归这里。能用脚本或测试拦住的，同时做成代码。
- 拿不准是否仍成立的，列出来问用户。
- 根目录 AGENTS.md 换成本技能目录下 `templates/AGENTS.md`，整份照搬。它要求写汇报、文档和界面文字时用 hypo-exp；宿主里没有这个 skill 时，告诉用户按 Hypo-Workflow 的 README 装上。

## 文档地图和分区规则

- 按项目类型用 `templates/起步/` 下的开发、研究、写作之一，出文档地图和分区 AGENTS.md 初稿。
- 地图里只放项目真有的东西；没有的分区先不建。
- 和用户讨论，确认后写进 RULES.md 和各分区 AGENTS.md。

## 需求文件

- 从代码和用户这次说的话里建初稿；读取现有 AGENTS.md、CLAUDE.md，把仍然成立的产品行为规则搬进需求文件，不从要归档的过程记录转写结论和进度。
- 按功能切分，每个功能一个文件，放地图写的位置。
- 先填“现在、代码、测试”，没有内容的整节删掉；其他内容和用户逐步补。
- 研究项目对应写研究线 README，写作项目对应写大纲和设定。

## 审核分级

- RULES.md 必须保留“审核分级”：通用定义照模板，带用户为每一级填上本项目的例子，不留（填）占位。
- 用项目真实入口、数据和“不能坏”来讨论例子，分清会悄悄出错、明显出错、以后有代价和纯偏好四类。

## 协作板

- BOARD 只写目录占用和留言，不写做到哪、下一步或已完成的事。下一步放在 STATUS“下一步”，等用户决定的事放在 STATUS“卡在哪”。
- 没有 BOARD.md 时，按 `templates/BOARD.md` 的结构建文件，删除模板示例行，只登记当前对话。已有文件保留其他人的行；旧分道格式提示迁移，不直接覆盖。
- 每个对话一行，四段用 `·` 分隔：工具名加开工月日时分、在做什么、占用目录、预计结束。目录不写到文件；预计时间快不够时，自己往后改。
- 用 `--as "<自己那行的名字>"` 认领，优先于备用环境变量 `HW_BOARD_NAME`。

## 收尾

- 跑 `hw check --as "<自己那行的名字>"`，把结果和它指出的问题在对话里讲清楚。
- 用户交代的事做完、改动已提交，删掉自己的占用行。
- 汇报：建了哪些文件、地图长什么样、哪些事等用户决定。

## 不要做

- 不写黑词：免责尾巴、自证标注、内部代号、编号、hash。
- 不在文档地图外新建记录，不发明新的记录系统。
- 不把要归档的过程记录里的结论和进度搬进新文档。
- 只处理接入范围内的文件；归档去向和新增分区尚未确定时先问用户。
