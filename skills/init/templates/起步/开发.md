# 开发项目起步：给执行 init 的 Agent 看

## 适合什么项目

有代码、有用户、会持续改的产品或工具。

## 建议的文档地图

| 放什么 | 在哪 | 怎么写 |
| --- | --- | --- |
| 给用户看的说明 | `README.md` | 是什么、怎么装、怎么用 |
| 产品现在的样子 | `docs/需求/<功能>.md` | 见 `docs/需求/AGENTS.md` |
| 用户认可的界面 | `docs/截图/` | 验收参照，见 `docs/截图/AGENTS.md` |
| 部署与运维 | `docs/运维/<主题>.md` | 只写现在怎么部署、怎么排障 |
| 过程材料 | `docs/材料/` | 原样保存，不再更新 |
| 整体进度 | `STATUS.md` | 只写走到哪、下一步 |

## 分区规则

### docs/需求/AGENTS.md

```markdown
# 需求：给写这个目录的 Agent 看
- 一个功能一个文件，文件名就是功能名。
- 只用固定小标题：现在、规则、不能坏、牵连、代码、测试、未定。
- 现在写用户能看懂的行为；代码写到“文件: 函数”。
- 改主意就改写“规则”里那一条，不追加新段落。
```

### docs/截图/AGENTS.md

```markdown
# 截图：给放验收图和写界面代码的 Agent 看
- 一个界面一组图，文件名写界面名和状态。
- 图是验收参照，实现照图和需求文件写，不复用 mock 的代码。
- 界面改了，先给用户看新图，认可后再换掉旧图。
```

### docs/运维/AGENTS.md

```markdown
# 运维：给部署和排障的 Agent 看
- 一个主题一个文件，文件名就是主题。
- 只写现在怎么部署、怎么重启、怎么排障。
- 服务器地址用占位符，密码和密钥不写进仓库。
```

### docs/材料/AGENTS.md

```markdown
# 材料：给翻旧资料的人看
- 会议记录、日志、导出文件原样放这里，文件名带日期。
- 放进来之后不再改。
- 这里的内容可能过时，用之前先核对；结论写进需求文件或 STATUS。
```
