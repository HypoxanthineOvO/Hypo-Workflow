# v13.1.0-alpha.1 发布说明

[English](../en/release/v13.1.0-alpha.1.md)

v13.1.0-alpha.1 发布于 2026-05-30。这是 13.1 系列的 alpha 版本，交付 C18 指令质量审查与集成同步方案：增强 `/hw:audit`，新增 `/hw:quality` 与 `/hw:optimize`，并把跨 `Codex-VSP`、`VSP-Open-Code` 等集成仓库的同步定义为开发/发布门禁而不是用户命令。版本标记为 alpha，不声明稳定发布。

## 重点

- **Audit 工程化升级**：`/hw:audit` 改为 Intake-first 审计，使用 Experience、Engineering、Risk 三视角，并通过 Critical blocking 与 Action Queue 收束。
- **Quality 一等入口**：新增 `/hw:quality`，输出代码质量 scorecard、baseline/compare、review notes 和可执行 Action Queue。
- **Optimize 闭环入口**：新增 `/hw:optimize`，按 Audit+Quality -> Implement/Test -> Audit+Quality 循环执行，并保留 backup、correctness、budget 和 validation gates。
- **集成同步门禁**：新增 integration sync 规范，明确同步不是 `/hw:*` 用户命令，而是 Hypo-Workflow 功能更新后的目标仓库适配流程。
- **目标仓库适配**：已将 C18 指令能力同步到 `~/Codex-VSP` 和 `~/VSP-Open-Code`，并在目标仓库内写入记录。
- **反馈回流路径**：普通对话/Journal 记录可以分类为 audit、quality、optimize、integration_sync 候选，再由用户确认后升级为 Knowledge、规则或指令来源。

## 修复

- 修正命令清单、OpenCode/Cursor/第三方适配器和文档中的 `/hw:*` 命名边界，使 `quality`、`optimize` 作为 Workflow 命令暴露，而 integration sync 不暴露为用户命令。
- 明确源仓库与目标集成仓库边界：源仓库维护命令语义、Skill/spec、生成器和 release gate；目标仓库根据当前状态适配并记录。
- 修复 OpenCode 目标适配中 reminder 文案暴露伪命令名的问题，确保模型不会看到 `/hw:integration-sync` 作为可执行用户入口。
- 刷新 OpenCode adapter、compact 派生物和文档生成物，保证发布前 `sync --check-only` 为 fresh。

## Alpha 边界

- 本版本准备 release commit、tag 和 push，但不执行 npm publish。
- 远端 release 页面创建需要单独确认。
- `Codex-VSP` 与 `VSP-Open-Code` 目标仓库保留其既有 dirty worktree；C18 只记录并验证本轮适配范围，不清理目标仓库无关改动。
- Integration sync 仍是开发/发布门禁，不是用户 slash command。
