# v13.1.0-beta.3 发布说明

[English](../en/release/v13.1.0-beta.3.md)

v13.1.0-beta.3 发布 manifest-based Workflow 核心和 Host Contract v1。Hypo-Workflow 现在拥有生命周期语义、Runtime、Records、Receipts、Recovery Journal 与 workspace 写入权威；Codex 和 OpenCode 只消费经过校验的发行版与只读 projection。

## 重点

- 公共表面固定为 `guide`、`init`、`goal`、`plan`、`cycle`、`maintain`、`resume`、`accept`、`reject` 九个命令。
- Host Status projection 使用严格递归 schema；损坏、失效、旧格式和敏感字段均 fail closed。
- Codex plugin ZIP 与 portable ZIP 使用确定性文件顺序和时间戳，release manifest 绑定源码 commit 与 SHA-256。
- OpenCode 可以校验真实 portable ZIP 的外层、内部文件、installed descriptor 和 command manifest，再原子激活并保留一次 rollback。
- 删除操作必须绑定精确 manifest 和一次性 Receipt，执行后留下可核查报告。

## 修复与兼容性变化

- 旧 Workflow runner、legacy writer、conversation capture 和退役命令不再是生产入口。
- Codex 从已安装 plugin cache 发现 Workflow；OpenCode 从 active installed release 读取命令，不再依赖并排源码仓库。
- Legacy workspace 只提供诊断并引导 `/hw:init`，宿主不会偷偷迁移或写回旧状态。

## 验证

- Hypo maintained Core `486/486`、scenarios `8/8`、Bootstrap `67/67`。
- Codex Host/routing/TUI/palette `5/5 + 4/4 + 8/8 + 1/1`，`cargo check` 通过。
- OpenCode Host/真实 ZIP `7/7`、相关 broad `26/26`，typecheck 通过。
- 两次构建 checksum 完全一致；真实 portable ZIP 已在临时 active root 通过完整安装链。

## Beta 边界

- 本版本不执行 npm publish。
- VSP-Codex 与 VSP-Open-Code 使用各自独立版本和 GitLab Release，不与本仓库标签混用。
- 用户目录安装、Hook re-trust 和目标宿主的 provider/model prompt 调优仍是独立显式操作。
