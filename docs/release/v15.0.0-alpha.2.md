# v15.0.0-alpha.2 发布说明

[English](../en/release/v15.0.0-alpha.2.md)

v15.0.0-alpha.2 让 v15 的语义工作流更适合跨项目采用，并重建 current release gate 的可信边界。History Refresh 不再依赖 Hypo-Workflow、C022、固定 Cycle 数量或固定文案；测试体系明确区分当前合同与只用于追溯的历史/fixture evidence。

## 主要变化

- History Refresh 从有效 manifest `project_id`、package name 或 workspace basename 派生项目身份，并支持任意 semantic Cycle、root legacy Cycle 与动态历史数量。
- 缺失 manifest 仅在明确批准后以 manifest-last 方式创建；已有有效 manifest 保持字节不变，损坏 manifest 与 stale preview 在任何写入前 fail closed。
- Core inventory 递归覆盖 179 个 test/spec，Scenario inventory 覆盖 76 个注册项；每一项均进入 `maintained`、`quarantined` 或 `excluded` 分类。
- `maintained` 是当前 release gate；`excluded` 只保留 fixture-owned 或 retired evidence，两个 runner 都拒绝显式执行它。
- Maintained runner 对 skip、TAP `1..0`、catalog 漏项和 Scenario 零匹配 fail closed，避免“没有实际执行测试”的假绿。
- public command、Bootstrap 数量与 History 输出从 authority 或输入派生；current gate 不再依赖 live repository snapshot、committed release artifact、retired API 或偶然文案/布局。

## 兼容性

- Official Codex 仍是唯一当前源端支持面，公共发现面保持十个 focused Skills 与六类语义/安全 Hooks。
- Host Contract v1 继续服务 legacy compatibility；新语义 workspace 仍通过普通文件恢复。
- `excluded` 不表示已删除历史证据。未来恢复相应能力时，必须基于 current API 重写合同并重新分类。

## 验证

- Core inventory：179 = 67 maintained + 0 quarantined + 112 excluded。
- Scenario inventory：76 = 8 maintained + 0 quarantined + 68 excluded。
- Maintained Core：709/709 通过，0 skipped；新增回归覆盖 Codex SemVer build metadata 与 artifact path 的 release schema 合法性。
- Maintained Scenario：8/8；History Refresh focused：12/12；最终受影响 focused：73/73。
- 10/10 primary 与 10/10 independent reviewer 完成全量双重审计；最终独立 diff 审计无未解决 High/Medium finding。
- 发布候选继续要求构建后校验 ZIP 内容、manifest/checksum、干净解压运行时与连续构建可复现性。

## 升级说明

- 新版本只对新 Session 生效；仍引用旧 `PLUGIN_ROOT` 的 Session 必须保留其固定 cache，直到自然结束。
- 安装或重装、marketplace/config 修改与 Hook trust 变更不属于源码分发准备，必须按目标环境单独执行并验证。
