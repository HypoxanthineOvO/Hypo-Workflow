# v12.5.0 发布说明

[English](../en/release/v12.5.0.md)

v12.5.0 发布于 2026-05-12，重点是把 GitHub PR #7 中有价值的 audit governance 能力干净移植到当前主线，同时避免把 `.pipeline/**` 运行态、生成文档和发布产物直接合入。

## 关键变化

- 从 PR #7 移植 audit governance hardening：`audit` 可在 milestone 完成前介入，rejection scope 覆盖 `milestone`、`feature` 和 `cycle`。
- 新增 audit memory runtime helper：支持 cycle-level audit memory、milestone-level audit delta、scoped audit summary，并明确 raw free-form conversation 不是 authority。
- 新增 rejection rework 和 blocked runtime helper：`implement` 只能 propose blocked，`audit` 才能 approve blocked；rework 必须带回原 prompt 与增量 scope。
- 强化 worker separation：acceptance 现在检查持久化的 `prompt_scope`、`changed_files` 和 worker scope evidence，阻止跨角色 ownership、scope 越界和 audit 写文件。
- `/hw:pr` create/review 增加 `.pipeline` 路径策略：默认阻止 `.pipeline/**` runtime 文件进入 PR payload，同时允许 `.pipeline/pr/**` 本地证据归档。

## 没有直接合入的内容

- 没有合入 PR #7 原分支里的 `.pipeline/**` runtime state、prompts、release notes 和 README/CHANGELOG 大包。
- 没有合入 `/hw:achieve` public command alias；该命令语义仍留给后续产品决策。
- 没有把 docs-only 的 Codex snapshot guidance 和 plan prompt architecture 断言混入本次治理移植。
