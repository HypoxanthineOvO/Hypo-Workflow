# v15.0.0-alpha.1 发布说明

[English](../en/release/v15.0.0-alpha.1.md)

v15.0.0-alpha.1 将 Hypo-Workflow 的默认工作方式从模型可见的 manifest 协议切换为人类可读的语义文件。Cycle 是迭代与归档边界；Goal、Plan、Experiment 和 Maintain 是围绕该边界工作的交付方式。旧 manifest Delivery 继续兼容读取，但不再决定新语义 Cycle 的恢复方式。

## 主要变化

- `.pipeline/INDEX.md` 成为语义入口；Cycle 使用 `PLAN.md`、`PROGRESS.md`、`EXECUTION.md`、Discussion 和最终 `SUMMARY.md` 表达完整生命周期。
- Plan 保留完整稳定 ID 表，Progress 镜像全部计划项和当前位置，Execution 记录目的、动作、结果、证据、计划影响、问题与下一步。
- Codex 只注册 SessionStart、UserPromptSubmit、PreToolUse、PermissionRequest、PreCompact 和 Stop 六类 Hooks。Hooks 提供上下文、讨论追加和窄安全边界，不是记录正确性的来源。
- Experiment 默认维护普通 YAML/Markdown；命名报告工具、content-addressed events 和物化 status projection 都是可选辅助或 legacy compatibility。
- Work Placement 为需要 authority 写入或资源 claim 的 Session 协调 repository、GPU、port、cache 和 output；未绑定 Session 仍可正常提问、诊断和维护普通文件。
- 一次性 History Refresh 为 20 个旧 Cycle 和 71 个 Memory Records 建立摘要/索引层；旧 archives、Manifest、Knowledge、Chats 和 7 个 live Delivery 原位保留。

## 兼容性

- Host Contract v1 保留给 legacy Delivery 和旧宿主，不是语义 workspace 的恢复前置条件。
- `hypo-workflow:accept`、`:reject`、`:resume` 等 Skill 优先读取语义索引和当前 Cycle；旧对象继续走兼容路径。
- 新版本只对新 Session 生效。仍引用旧 `PLUGIN_ROOT` 的 Session 必须保留其固定 cache，直到自然结束。

## 验证

- Hypo-Workflow maintained：704/704 通过。
- History Refresh：7/7 通过；20/20 历史 Cycle 的 Plan/Progress ID 对齐；重复激活返回 `unchanged`。
- 旧 archives 与 Manifest 的 SHA-256 在激活前后保持不变。
- VSP-Codex Host Contract 7/7、semantic/legacy routing 7/7、TUI command routing 11/11，合计 25/25 通过。
- 发布构建校验插件结构、ZIP 内容、锁文件依赖、manifest checksum 与干净解压后的运行时加载。

## 升级要求

- 安装前快照仍被活动 Session 引用的旧 cache，并在安装流程内恢复到原绝对路径。
- 安装后重新信任当前六类 Hook；旧十 Hook 的 trust 记录不应继续启用。
- 使用全新 Session 验证语义 Cycle 恢复、legacy Delivery 路由、Experiment 普通文件记录和 Stop/PreCompact 行为。
