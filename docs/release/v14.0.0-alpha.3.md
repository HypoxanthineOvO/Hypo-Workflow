# v14.0.0-alpha.3 发布说明

[English](../en/release/v14.0.0-alpha.3.md)

v14.0.0-alpha.3 是一个最小 Codex Hook reminder 并发修复。它不改变 Recovery schema、Hook 权威或公开 Workflow 入口。

## 修复

- `PostToolUse` 不再向 Recovery Journal 追加 `tool.completed`，也不 replay Journal 来判断是否已经输出 reminder。
- reminder 使用 workspace runtime 下的 digest marker 去重。digest 同时包含 active object、既有 worktree-effect reminder key 和最终提示文本，不会把不同 active object 或不同提示内容合并。
- 父目录可重复安全创建；最终 digest marker directory 只通过一次非递归 `mkdir` 原子 claim。claim 成功的 Hook 输出提示；只有 `EEXIST` 后重新校验为 workspace 内普通 marker directory 才表示 dedupe loser，普通文件、symlink 或其他非法节点按 Hook error 失败。
- `Stop`、`PreCompact` 和 `PostCompact` 保持 v14.0.0-alpha.2 的 `main/main` Recovery writer 语义。Subagent writer、Ambient Maintain writer 和 Recovery Journal Core 不变。

## Recovery 语义

- `PostToolUse` 不创建 Recovery event 或 writer stream；marker 只负责短提示去重，不参与 replay、cursor、Capsule 或 Pack。
- `Stop` 继续在 `main/main` stream 追加唯一 `turn.agent`，compact Hooks 继续使用既有恢复路径。
- marker 位于 `.pipeline/runtime/codex-hooks/reminders/`，属于 workspace runtime 派生状态，不是 Record、Receipt 或 Recovery 权威。

## 验证

- 真实 multi-process 回归在同一 workspace、session 和 active delivery 下并发运行 16 条相同 `PostToolUse` 与一条 `Stop` wrapper。
- 所有 wrapper 必须 exit 0；总共只输出一个 reminder，`PostToolUse` 不新增 Journal event 或 stream，`Stop` 只产生一个 `turn.agent`。
- 12288-byte Recovery restore、既有 compact restore、cursor/replay、worker event 与 Journal baseline 测试继续作为回归边界。

## 已知边界

- marker claim 与提示输出之间仍存在进程崩溃窗口：claim 后、输出前崩溃可能使该提示保持已去重状态。
- 不同 digest 的空 marker directory 当前没有自动 retention/cleanup，数量会随不同 reminder effect 增长。它们不进入 Recovery replay、cursor、Capsule 或 Pack；删除后会允许相同 reminder 再次输出，且不会改变恢复权威。
