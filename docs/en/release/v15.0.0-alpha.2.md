# v15.0.0-alpha.2 Release Notes

[中文](../../release/v15.0.0-alpha.2.md)

v15.0.0-alpha.2 makes the v15 semantic workflow safer to adopt across projects and rebuilds the trust boundary of the current release gate. History Refresh no longer depends on Hypo-Workflow, C022, a fixed Cycle count, or fixed prose. The test system now distinguishes current product contracts from historical and fixture-only evidence.

## Highlights

- History Refresh derives project identity from a valid manifest `project_id`, package name, or workspace basename, and supports arbitrary semantic Cycles, root legacy Cycles, and dynamic history counts.
- A missing manifest is created only after explicit approval and remains the last write. Existing valid manifest bytes are preserved, while malformed manifests and stale previews fail before any write.
- Core inventory recursively covers 179 test/spec files and Scenario inventory covers 76 registered entries. Every item is classified as `maintained`, `quarantined`, or `excluded`.
- `maintained` is the current release gate. `excluded` retains fixture-owned or retired evidence, and both runners reject attempts to execute it explicitly.
- Maintained runners fail closed on skips, TAP `1..0`, catalog omissions, and zero-match Scenario patterns, preventing green results with no effective test execution.
- Public commands, Bootstrap counts, and History output are derived from authorities or inputs. The current gate no longer depends on live repository snapshots, committed release artifacts, retired APIs, or incidental prose and layout.

## Compatibility

- Official Codex remains the only current source-side support surface, with ten focused Skills and six semantic or safety Hook events.
- Host Contract v1 continues to serve legacy compatibility. New semantic workspaces still recover from ordinary files.
- `excluded` does not mean historical evidence was deleted. Restoring a capability requires a contract rewritten against the current API and a new classification review.

## Upgrade Notes

- The new version applies only to new Sessions. Sessions pinned to an older `PLUGIN_ROOT` must retain that exact cache until they end naturally.
- Installation or reinstallation, marketplace/config changes, and Hook trust updates are outside source distribution preparation and require separate target-environment execution and validation.
