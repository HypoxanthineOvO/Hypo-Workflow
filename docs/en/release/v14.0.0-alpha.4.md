# v14.0.0-alpha.4 Release Notes

[中文](../../release/v14.0.0-alpha.4.md) | English

v14.0.0-alpha.4 allows one Project to safely maintain multiple Deliveries and Experiments while keeping each Session bound to exactly one selected Work Item. It retains the Codex Hook concurrency fixes from v14.0.0-alpha.3 and extends concurrency control to repositories, worktrees, GPUs, ports, caches, and output locations.

## Features

- A **Repository Target registry** separates stable repository identity from mutable locators. Every repository retains one permanent primary integration target and may register alternate integration targets.
- A **Work Placement registry** treats Goals, Plans, and compatible Cycles as Delivery Work Items while Experiments remain independent Work Items. Multiple Work Items may be active in one Project.
- Every **Session** explicitly binds one Work Item. Multiple candidates produce `selection_required`; the Session never silently inherits legacy `active.delivery` or mixes two jobs in one context.
- Atomic Placement preflight evaluates repository access, builds, GPUs, ports, caches, filesystem claims, and outputs. Its decisions are `shared`, `isolated_worktree`, `isolated_resources`, or `blocked`.
- Different source snapshots and source-changing work return bounded Git worktree Host descriptors. Relocatable resources receive deterministic isolated locators. Core does not execute Git, processes, or GPU commands.
- Lease renewal and **fencing** prevent two processes from acquiring the same exclusive resource. An expired owner cannot revive, release a successor's resource, or record integration after takeover.
- Source-changing work requires **integration** evidence bound to the registered Repository Target checkout, branch ref, source/result commits, target HEAD, and ancestry. The completion gate revalidates the proof and provides no abandon bypass.

## Fixes

- An expired-only Placement registry now leaves a manageable empty-candidate state instead of permanently blocking UserPrompt, PreToolUse, or PermissionRequest.
- A selected Experiment safely continues through PreCompact/PostCompact when no Delivery Recovery Capsule exists.
- Host status projects available Work Items, Session selection, and expired leases while preserving legacy workspaces that do not yet have a Placement registry.
- The alpha.3 atomic reminder marker remains intact, and safe finalization of an equivalent superseding Host projection now works with the newer writer lease/fencing kernel.

## Validation

- The failure-first Placement contract began at `1 fail / 8 skip`; the final Repository, Placement, Session, fresh-process fencing, integration, and legacy contracts all pass.
- Placement, Host, Hook, and workspace transaction cross-regression: `59/59 PASS`.
- Maintained full suite: `710/710 PASS`.
- Independent implementation audit: `PASS`, with `0 blocking findings`.
- Host plugin and portable bundles are built from a clean source commit and validated through manifests, SHA-256 checks, and a temporary installation before publication.

## Known Boundaries

- Core validates and returns structured Host descriptors; the Host still performs real worktree creation, GPU/port allocation, experiment processes, and Git integration.
- The Cryo-Computing Accel-Sim/Trace topology is covered by a filesystem fixture. Publishing this release does not start a real experiment.
- Placement history remains retained. A future explicit retention/compaction operation can prune history without changing active lease or fencing semantics.
