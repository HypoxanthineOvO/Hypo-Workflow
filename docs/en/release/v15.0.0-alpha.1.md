# v15.0.0-alpha.1 Release Notes

[中文](../../release/v15.0.0-alpha.1.md)

v15.0.0-alpha.1 changes Hypo-Workflow's default model-facing workflow from a manifest protocol to readable semantic files. Cycle is the iteration and archive boundary; Goal, Plan, Experiment, and Maintain are delivery modes around that boundary. Existing manifest Deliveries remain readable through a compatibility path, but they no longer govern recovery for new semantic Cycles.

## Highlights

- `.pipeline/INDEX.md` is the semantic entry point. A Cycle uses `PLAN.md`, `PROGRESS.md`, `EXECUTION.md`, Discussion, and a final `SUMMARY.md` for its complete lifecycle.
- Plan keeps the complete stable-ID table, Progress mirrors every plan item and current position, and Execution records purpose, actions, results, evidence, plan impact, problems, and the next step.
- Codex registers only SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PreCompact, and Stop. Hooks provide context, discussion capture, and narrow safety boundaries; they are not the source of record correctness.
- Experiment defaults to ordinary YAML or Markdown. Named reporting tools, content-addressed events, and materialized status projections are optional helpers or legacy compatibility surfaces.
- Work Placement coordinates repositories, GPUs, ports, caches, and outputs for Sessions that need authority writes or resource claims. An unbound Session can still ask questions, diagnose problems, and maintain ordinary files.
- A one-time History Refresh adds a summary and index layer for 20 historical Cycles and 71 Memory Records while preserving old archives, the Manifest, Knowledge, Chats, and seven live Deliveries in place.

## Compatibility

- Host Contract v1 remains for legacy Deliveries and older hosts; it is not a prerequisite for semantic workspace recovery.
- `hypo-workflow:accept`, `:reject`, `:resume`, and related Skills prefer the semantic index and current Cycle while retaining the old-object compatibility path.
- The new version applies only to new Sessions. Sessions pinned to an older `PLUGIN_ROOT` must retain that exact cache until they end naturally.

## Upgrade Requirements

- Snapshot any old cache still referenced by an active Session and restore it at the same absolute path during installation.
- Trust the current six Hook definitions after installation. Old ten-Hook trust records must remain disabled.
- Validate semantic Cycle recovery, legacy Delivery routing, ordinary Experiment records, and Stop/PreCompact behavior in a fresh Session.
