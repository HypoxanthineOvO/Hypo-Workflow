# v14.0.0-alpha.6 Release Notes

[中文](../../release/v14.0.0-alpha.6.md)

v14.0.0-alpha.6 removes unnecessary coupling between Experiment records and optional Hook capabilities, and restores missing CLI-facing Root Core exports. Hooks provide reminders and guardrails, ordinary files preserve readable records, and an unavailable helper no longer prevents the host Agent from continuing the work.

## Experiment Records

- The default protocol uses one readable `experiment.yaml` plus a separate YAML file for each Attempt; see `docs/en/reference/experiment-records.md` for the format and fields.
- Named reporting tools, BatchReport-like host capabilities, content-addressed events, hash validation, and materialized status projections are optional helpers or compatibility surfaces.
- When a helper is unavailable, the Agent updates the ordinary YAML directly. Experiment commands, long-run supervision, result analysis, and record updates must continue.

## Hook Behavior

- When a Session is not bound to a Work Item, `SessionStart` and `UserPromptSubmit` provide visible context and candidates without blocking ordinary prompts or all tools.
- Work Placement still governs Workflow authority writes and resource claims such as GPUs, ports, caches, and output directories; it is no longer a global prerequisite for host work.
- Hooks no longer infer user meaning from keywords and automatically persist it to an inbox. The main Agent identifies explicit durable requirements, preferences, decisions, and feedback, then persists them through Maintain.
- Auxiliary Hook failures return a warning and allow host work to continue. Guardrails for explicit deletion and controlled destructive operations remain strict.

## CLI And Planning Fixes

- Root Core again exports sync, TUI, maintenance, project-event, and notification APIs, fixing the missing `buildGlobalTuiModel` export that prevented `hypo-workflow sync --check-only` from starting.
- Write-capable sync remains retired. `--check-only` inspects derived artifacts without modifying the target workspace.
- Goal and Plan Discussion display Discover, Technical, and Architecture artifacts together and ask only at material decisions or the final Proposal. Fixed question rounds and ceremonial per-phase confirmation gates are removed.

## Verification

- The maintained Core suite covers Hook, Experiment protocol, planning, and root-export regressions.
- The Codex Hook smoke test covers real wrapper input/output and the fail-open / guardrail boundary.
- Release validation checks plugin structure, ZIP contents, lockfile dependencies, manifest checksums, and runtime loading from a clean extraction.

## Upgrade Notes

- The new version applies to new Sessions. Sessions still pinned to an old `PLUGIN_ROOT` should retain that cache until they end naturally.
- Legacy Experiment events and projections remain readable, but new records should prefer the ordinary YAML protocol.
