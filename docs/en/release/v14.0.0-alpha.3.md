# v14.0.0-alpha.3 Release Notes

[中文](../../release/v14.0.0-alpha.3.md)

v14.0.0-alpha.3 is a minimal Codex Hook reminder concurrency fix. It does not change Recovery schemas, Hook authority, or public Workflow routes.

## Fix

- `PostToolUse` no longer appends `tool.completed` to the Recovery Journal or replays the Journal to decide whether a reminder was already emitted.
- Reminder dedupe uses a digest marker in workspace runtime. The digest includes the active object, the existing worktree-effect reminder key, and the rendered reminder, so distinct active objects or reminder content do not suppress each other.
- Parent directories are safe to create repeatedly. The final digest marker directory is claimed with one non-recursive atomic `mkdir`; the winner emits the reminder. Only an `EEXIST` target revalidated as an ordinary marker directory inside the workspace is a dedupe loser. Ordinary files, symlinks, and other invalid nodes fail through the Hook error contract.
- `Stop`, `PreCompact`, and `PostCompact` retain the v14.0.0-alpha.2 `main/main` Recovery writer semantics. Subagent writers, Ambient Maintain writers, and Recovery Journal Core are unchanged.

## Recovery Semantics

- `PostToolUse` creates no Recovery event or writer stream. The marker only deduplicates a short reminder and does not participate in replay, cursors, Capsules, or Packs.
- `Stop` continues to append one `turn.agent` to the `main/main` stream, while compact Hooks retain their existing recovery path.
- Markers live under `.pipeline/runtime/codex-hooks/reminders/`. They are derived workspace runtime state, not Record, Receipt, or Recovery authority.

## Validation

- A real multi-process regression concurrently runs 16 identical `PostToolUse` wrappers and one `Stop` wrapper against one workspace, session, and active delivery.
- Every wrapper must exit 0. Exactly one reminder is emitted, `PostToolUse` adds no Journal event or stream, and `Stop` produces exactly one `turn.agent`.
- The 12288-byte Recovery restore, existing compact restore, cursor/replay, worker event, and Journal baseline tests remain regression boundaries.

## Known Boundaries

- A process can fail after claiming a marker but before emitting its reminder, leaving that reminder deduplicated.
- Empty marker directories for distinct digests currently have no automatic retention or cleanup, so their count grows with distinct reminder effects. They do not enter Recovery replay, cursors, Capsules, or Packs; removing them allows the same reminder to be emitted again without changing recovery authority.
