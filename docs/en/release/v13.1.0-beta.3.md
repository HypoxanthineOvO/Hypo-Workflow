# v13.1.0-beta.3 Release Notes

[中文](../../release/v13.1.0-beta.3.md)

v13.1.0-beta.3 ships the manifest-based Workflow Core and Host Contract v1. Hypo-Workflow now owns lifecycle semantics, Runtime, Records, Receipts, the Recovery Journal, and workspace writes. Codex and OpenCode consume verified releases and a bounded read-only projection.

## Highlights

- The public surface is exactly nine commands: `guide`, `init`, `goal`, `plan`, `cycle`, `maintain`, `resume`, `accept`, and `reject`.
- Host Status uses strict recursive validation and fails closed for damaged, invalidated, legacy, unknown, or sensitive data.
- Deterministic Codex plugin and portable ZIP artifacts bind a source commit and SHA-256 checksums.
- OpenCode verifies the real portable ZIP, every internal file, the installed descriptor, and the command manifest before atomic activation with one rollback slot.
- Destructive cleanup requires an exact manifest and a single-use Receipt, followed by an auditable execution report.

## Fixes and Compatibility Changes

- The legacy Workflow runner, writers, conversation capture, and retired command paths are no longer production entrypoints.
- Codex discovers Workflow through the installed plugin cache; OpenCode reads the active installed release instead of a sibling source checkout.
- Legacy workspaces are diagnostic-only and route adoption through `/hw:init`.

## Tests

- Codex Host/routing/TUI/palette `5/5 + 4/4 + 8/8 + 1/1`, with `cargo check` passing.
- OpenCode Host/real ZIP `7/7`, related broad tests `26/26`, and typecheck passing.

## Beta Boundary

- This release does not publish npm packages.
- VSP-Codex and VSP-Open-Code keep independent versions and GitLab releases.
- User-directory installation, Hook re-trust, and target-owned provider/model prompt tuning remain separate explicit operations.
