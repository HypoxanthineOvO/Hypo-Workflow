# Hypo-Workflow 3.0：给用 Agent 做项目的人看

它让项目的文档和代码一直对得上。

## 它是什么

一套项目文档规范，加一个只读的查询和检查工具 hw。装进项目后，Agent 按同一套规则记文档、写提交、交接工作。

## 解决什么问题

用 Agent 改项目，久了常见这些事：

- 代码改了，文档还是旧的，下一个人照着旧文档做错。
- 规则只追加不替换，没人知道哪条还有效。
- 假完成：测试通过、文件写好就说做完了，用户真实使用的入口没跑过。
- 汇报只给文件路径和术语，用户看不到结论。
- 按日期堆一堆报告，没人读，也说不清项目现在什么样。

3.0 只做一件事：边用边改时，文档和代码一直对得上。

## 安装

在仓库目录里：

```bash
uv tool install .
```

之后全局有 `hw` 命令。没装的机器也能在仓库目录直接跑：`python3 -m hw ...`。

## 接入一个项目

把 `skills/init/` 装进你的 Agent 宿主，让它能读到 SKILL.md；或者直接对 Agent 说：

> 用 Hypo-Workflow 接入这个项目，规则看 skills/init/SKILL.md。

接入会做这些事：扫描项目；把旧记录整块归档；把现有项目规则整理进 RULES.md；根目录换成通用 AGENTS.md；按开发、研究、写作三种起步模板出文档地图；从代码建需求文件初稿；分工表留空问你。动手前会先把要改的文件列给你确认。

## 接入后项目里有什么

| 文件 | 内容 |
| --- | --- |
| AGENTS.md | 所有 Agent 同一份通用规则 |
| RULES.md | 文档地图、分工、汇报格式、禁区、构建与测试 |
| STATUS.md | 项目走到哪、下一步、卡在哪、以后 |
| BOARD.md | 每个 Agent 在做什么、留言 |
| 分区 AGENTS.md | 这个分区怎么命名、写什么 |
| docs/需求/ | 产品现在的样子，一个功能一个文件 |

小项目可以只有前三个，其他用到再建。

## hw 命令

| 命令 | 做什么 |
| --- | --- |
| `hw map` | 列出文档地图 |
| `hw find <词>` | 找相关需求、牵连、代码、测试，以及 BOARD 里在动这些文件的人 |
| `hw status` | STATUS 和 BOARD 摘要；等用户决定的事；未提交文件和 git status 是否一致 |
| `hw log <功能>` | 列出动过这个功能的提交 |
| `hw check` | 检查改了代码没改文档、提交格式、黑词、地图、README、BOARD、敏感文件 |
| `hw handoff` | 找最近的会话，抽出用户的话和最后几轮汇报 |
